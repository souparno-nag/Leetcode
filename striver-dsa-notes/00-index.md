## How each problem is laid out

- **Problem Statement** with worked examples.
- **Intuition**: the idea behind the solution, following the video where there is one.
- **Approach N** for every approach discussed (brute → better → optimal; for DP: recursion → memoization → tabulation → space optimisation), each with its complexity and code in **C++ and Java**.
- **Edge Cases & Pitfalls** and **Key Takeaways**.

## Markers

- *(not in video)*: an approach or detail added beyond what the video covers.
- *no video*: the sheet has no video for this problem; the notes were prepared independently.
- *video not transcribed*: a video exists but YouTube served no usable captions, so the notes were prepared independently.
- A short note at the top of a problem explains any substitution, for example when the sheet's link pointed to a neighbouring lecture or to a different LeetCode problem.

## Verification

Every C++ code block was compiled (g++ -std=c++17) and every Java block was compiled (javac). The C++ approaches were then cross-checked against each other, and against a brute force where one exists, on random inputs, and worked examples were checked by running the code.
